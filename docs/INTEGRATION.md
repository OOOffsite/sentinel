# Sentinel v0.4.0 — OpenRig-native integration module (ADR-S01)

Status: implemented local companion; proposed upstream integration; 2026-11-24. Atlas wiki revision 0.2.0. Existing METRICS v4 and FBGM versions unchanged. Sentinel simulation contract 1.0.0 preserved without alteration.

## Decision
Accept: independent read-only observability module using OpenRig's documented telemetry boundary and smota/openrig-telemetry (Apache-2.0), OTLP HTTP JSON, an SQLite metadata journal, local HTTP snapshots, and one shared skill projected natively into Claude Code and Codex. Reject redundant per-seat hooks, daemon database access, a fork for the first prototype, and inferring exact work/communications from queue data. Defer upstream native UI patch and optional explicit message endpoint instrumentation until upstream compatibility tests and approval. Keep existing Sentinel v0.2 animated simulation separate from the observed view. Never use simulation as a fallback when actual observations are missing.

## Boundaries and components
OpenRig remains the sole agent and queue authority. The exporter handles source cursor, retry, retained-window coverage, checkpoints, and sample extraction; Sentinel does not implement an alternative poller. Pin reviewed exporter commit `1beecce96befec880a93f60b11d83b44d7347620` before first integration. Source docs reviewed at OpenRig v0.7.21; installed version must be checked on host. Exporter source (Node 22/24) is an independent dependency, not vendored. Start one exporter per journal/namespace. Local receiver implements only the exporter scope version 1 `logs,metrics` subset (JSON, no protobuf/compression, traces deferred). OTLP data accepted only from the configured source namespace and one exporter instance. The system is local-only under a trusted OS account, not a security boundary between local users or agents. Browser Origin, Host, Fetch Metadata guards prevent common cross-origin requests; they are not authentication. No remote exposure or production secrets. Use a separate read-only broker with scoped auth and TLS before exposing beyond loopback or across untrusted seats. No external model calls, installation side effects, or changes to OpenRig daemon/harness config from the collector.

## Module contract inventory
- `module.json`: Sentinel-owned package manifest, not an upstream OpenRig plugin manifest. `module-manifest.schema.json` describes it.
- `module-config.schema.json`: single namespace, freshness TTL, immutable-node-to-Atlas-seat binding map. Empty bindings intentionally permitted. Node and native numeric IDs remain strings; binding uniqueness checked at runtime. Identity mapping immutable per journal; change requires a new config/journal or deliberate migration outside prototype.
- `observation.schema.json`: allowlisted normalized record separate from CloudEvents simulation. Raw exporter batch is never stored. Metric values/counts and nanoseconds decimal strings; source namespaces, instance and node IDs explicit. Unknown queue-state value represented as unknown. `seat-observation`, `snapshot`, `status`, `history`, `roster` schemas govern the local read API. `types.d.ts` supplies frontend declarations. OpenAPI 3.1 documents routes; request schema describes OTLP subset envelope, implementation verifies individual fields. Simulation event/recording schemas carried forward unmodified (the simulation recording references its original telemetry-event schema; retain same filename).
- `plugin/`: portable Agent Plugins manifest plus Claude/Codex compatibility manifests and one `sentinel-monitor` skill. Skill is read-only; no hooks, MCP servers, or automatically spawned processes. Optional for unmanaged harness sessions. OpenRig native projection uses `resources.skills` and `profiles.default.uses.skills` instead; no redundant installation. The generated agent specs use JSON-compatible YAML as in Atlas 0.1. `tools/project_skill.py` supports plan by default and explicit apply, copies the identical skill into each agent spec's resource directory, not into global user configuration. Do not apply during live launches; back up generated rig directory first. Projection is not a daemon modification.

## Data semantics and API
POST `/v1/logs`, `/v1/metrics`: bounded OTLP JSON, allowlisted exporter scope/namespace, transaction commits before acknowledgement; 400 for unsupported/malformed records, 413 for size, 415 for encoding, 503 on database failure. Exact normalized duplicates suppressed by SHA256; not a general-purpose OTLP receiver. Nonessential attributes (e.g. raw actor, queue body, paths, prompts, resource values outside allowlist, histogram bucket distributions, full diagnostics) are deliberately omitted. Distinct source records whose normalized projection is identical may collapse; counts of stored observations are not source event counts. No raw message payload storage. Cumulative counters/histogram counts are retained as source observations, not summed across snapshots or represented as performance estimates. No trace receiver in this version.
GET `/api/v1/status`: journal state, last receipt and unknown historical completeness; status is not proof source is reachable. GET `/api/v1/roster`: project-configured planned seat identifiers, team and runtime. GET `/api/v1/snapshot`: latest observed seat projections, TTL, last 40 log records and explicit `communication_available:false`; optional `at` is journal cursor, replay as of receipt time. GET `/api/v1/history?after=0&limit=100`: ordered bounded rows, continuation and `has_more`; sequence monotonic but may have holes (dedupe and database sequence allocation). Never equate journal ordering with source causality. A seek into the middle of a batch may show incomplete one-hot observations; unknown is safe, use end-of-batch cursor for operational comparisons. Production must implement stable snapshots, explicit event coverage, cursor epochs and bounded retention. Poll UI at 2s; this is not source polling cadence. Exporter seat samples at configured interval, e.g. 5s. Source sample age beyond TTL or future clock timestamps yields unknown; missing/unsupported needs-input is unknown. No observed sender/receiver, so observed UI draws no live message particles; working pulse means sampled working, not specifically coding. Unmapped observed nodes listed neutrally; all planned nodes remain dim until verified binding. No historical join to today's seat names. Bind only an immutable node known to belong to that roster seat; pseudonymized exporter IDs supported if confirmed by the operator. New checkpoint instance refused on same journal. Historical completeness remains unknown across daemon restarts; exporter captures gaps, Sentinel shows their normalized observations.

## Native enhancement proposal (upstream, not implemented)
1. Use existing OpenRig telemetry event schemas and UI route conventions; seek maintainer agreement before any new extension point. Do not invent `rig plugin install sentinel` semantics. OpenRig's existing plugin and agent-spec machinery concern agent resources/harnesses, not an established third-party daemon UI registration contract.
2. Add an optional versioned metadata projection for directed message dispatch/receipt, with immutable source+target node and tenure IDs, opaque message ID, stage, timestamps, coverage; exclude bodies, prompts, paths. Emit from authoritative transport boundary, not two client hooks. Delivery is not read/comprehension. Reuse existing transport delivery evidence if verified to expose the required endpoint identities. Negotiate scope version and compatibility fixture; unsupported fields remain unknown. Never place telemetry failure in execution critical path.
3. Add native dashboard navigation or a maintainer-approved companion URL, preserving existing auth and rig scoping; do not iframe a privileged local endpoint. Existing exporter integration should be sufficient for phase one. For agent sub-phases (coding/testing/review) use native provider OTLP or explicit structured approved task/build evidence only after identity and semantic mapping validation; reuse upstream bridge if feasible.
4. Move the observed renderer to Sentinel's animated simulation renderer only when distinct provenance and coverage gates pass. Keep v1 CloudEvents simulation and observation types independent; new explicit directed events require a versioned bridge schema. Do not animate hypothetical topology as observed communication.

## Acceptance and operations
M00 approval for source versions, integration repository, budget and security boundary remains required. M01 module contract review; M02 exporter interoperability against installed version and exact pinned commit; M03 explicit identity bindings with two stub or paper seats; M04 8-seat pilot and load/staleness/boot regression tests; M05 128 seats only if resource capacity and approval. Keep original 38 missions and IDs; these are Sentinel-specific sub-milestones, not changes to original DAG. Verify no additional model sessions, no agent settings modified, no hooks installed, no private payload captured, no duplicate writes on replay, correct unknown semantics. On any exporter incompatibility stop only Sentinel/exporter, retain database/checkpoint; do not restart OpenRig or discard history. Back up SQLite using SQLite online backup or stop service then copy database plus WAL/SHM as appropriate. Never delete checkpoint while exporter runs. For rollback stop the companion and exporter; restore saved generated AgentSpecs and remove only copied skill resources after review. No daemon restart is necessary for collector lifecycle. Do not expose the module remotely; retention/backpressure, per-user authorization, bounded journal size and actual 128-seat sustained performance must be validated before production. The package has no native OpenRig binary, exporter install, or plugin marketplace publication.
